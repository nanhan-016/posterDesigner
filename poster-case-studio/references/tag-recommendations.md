# 两轮案例匹配

## 字段与标签边界

读取 `assets/catalogs/tags.json` 后再打标。沿用原 52 个基础标签、18 小类与别名，不新增值。“无主体（不能扣图）”是请求中的写法，实际保存素材库规范值“无主体（不能抠图）”。

| 用户所说的类别 | 字段 | 新流程中的用途 |
| --- | --- | --- |
| 活动类型 | eventType | 第一轮匹配，单选 |
| 受众群体 | audience | 第一轮匹配，可多选 |
| 包含内容 | contentTypes | 第二轮匹配，可多选 |
| 主视觉侧重类型 | subjectType | 第二轮匹配，单选：单主体、多主体、无主体（不能抠图） |
| 主视觉侧重点类型 | visualFocus | 原库的另一个类别；保留，但不参与新两轮匹配 |
| 风格 | styleFamily | 第一轮统计输出，不用来匹配自身 |
| 排版／构图 | composition | 第二轮统计输出，不用来匹配自身 |
| 视觉小类 | visualSubtype | 用户选择对应路线，不参与案例相似度 |

原库 1318 条标签记录来自 2026-10-04 导入。记录包括标签与行号，不包括案例图片像素；本次未把后来 Excel O 列导入新推荐器。18 张本地图片是风格参考，不能说已查看 40／60 条案例图片。

## 确定性相似度

两个维度等权。每个维度的分数 = 用户该维度被案例命中的标签数 ÷ 用户该维度标签总数。总相似度 = 两个维度分数的平均。案例缺该维度时为 0；额外案例标签不扣分。

例：用户受众为 A、B；某案例活动类型命中且受众只命中 A，则第一轮相似度为 `(1 + 1/2) / 2 = 0.75`。

- 第一轮只匹配 eventType、audience；第二轮只匹配 contentTypes、subjectType。
- 两个维度都必须已确定且非空；第二轮还要求 materialUse.confirmed 为 true，且 subjectType 与用途一致。
- 排序：相似度降序，同分按原案例行号升序。没有随机抽样。
- 只保留相似度大于 0 的记录，不用完全无命中的行填满；最多 40／60，允许更少。没有沿用旧 0.55 阈值或旧七维权重。
- 所选大类、构图、小类、关键词、视觉重点、配色与照片条件都不能改变本轮检索排名。

## 统计与推荐门槛

第一轮在取出的案例内按 styleFamily 计数；第二轮按 composition 计数。同一行同一标签只计一次，一行多个不同风格分别各计一次，不按相似度加权，不分摊半条，也不按模板推算频数。

频数降序，同频按 tags.json 原目录顺序；先取前三名，再保留 count ≥ 9。8 条不推荐，9 条推荐。每轮 0–3 个候选，不能靠旧规则补足三个。不得为达到门槛调整样本大小、换同分规则、扩大数据集或改标签。

展示“类别出现条数／实际取出的案例数”，不是用户偏好概率、质量分数或全库比例。分类缺失的案例仍在检索样本里，但不为缺失输出类别贡献计数。

第一轮输出大类；大类下的现有小类／21 配方仅供选择，不能声称其频数由案例统计得到。照片必需配方可提示不可执行，但不能悄悄把统计大类换成第四名。没有达标项时说明证据不足，用户可从完整目录手动选择。

## 第二轮统计到 16 模板的映射

原案例只标了 9 类构图，未标 L01–L16。沿用 `recommendation-rules.json.compositionLayouts` 映射。每个达标构图选一个可用模板，最多三个。模板筛选参考选定风格、文字量、标题方向、保护区域与真实文字测量，仅在已有构图映射内调整；这些适配条件不改统计计数。

保留 16 模板供用户明确手动选择。S 形、四角与完整包围是近似映射，需要微调。映射模板全冲突时保留构图统计证据并说明暂无可用模板，不向用户展示遮挡候选，也不拿别类补位。多于八个信息字段无法完整容纳时扩展文字层，不删信息。

## 调用与审计

```bash
node scripts/recommend.mjs --brief /absolute/brief.json --stage style --output /absolute/style-match.json
node scripts/recommend.mjs --brief /absolute/brief.json --stage layout --output /absolute/layout-match.json
```

不指定 --stage 时计算 both；尚未确认素材用途不会得到第二轮候选。返回 round1／round2 的全部入选行号、命中项、相似度，styleRanking／layoutRanking 完整频数，styleFamilies／layoutGroups 达标项，以及映射模板与警告。将两轮结果与实际用户确认保存于项目私有记录。

```json
{
  "hasSourcePhoto": true,
  "selectedTags": {
    "eventType": ["展览展示类"],
    "audience": ["文化审美型"],
    "contentTypes": ["活动名称/时间/地点", "活动内容"],
    "subjectType": ["单主体"]
  },
  "materialUse": {"mode": "subject", "confirmed": true, "subjectCount": 1},
  "content": {"title": "用户实际标题", "body": "用户实际说明"}
}
```

materialUse 只能在实际选择后写 confirmed:true；无图的 title 模式可直接执行用户指定规则。subjectCount 是保留的不同主体数量，不是平铺次数；tile、blur、title 始终对应无主体标签。更改用途／数量后更新标签、重新执行第二轮；更改活动或受众后重新执行第一轮。

编辑器使用同一引擎。更改标签只重算建议，不自动替换当前风格、背景、配色、布局。完整目录按钮是手动选择，不是统计推荐。
